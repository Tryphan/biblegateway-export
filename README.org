#+title: BibleGateway Export
#+startup: overview

Export BibleGateway passages to *Emacs Org mode*, *Markdown*, or *plain text* from the command
line or directly into an Org buffer. Includes titles, editorial headings, chapter
and verse numbers, footnotes, cross-references, and copyright notices.

Version *2.2.0* is implemented in Python. The command remains =bg-export=, and
existing CLI options retain their meanings. No Ruby runtime or gems are needed.

Based on Jonathan Clark's
[[https://github.com/jgclark/BibleGateway-to-Markdown][BibleGateway-to-Markdown]]
(upstream commit =3d2104c6114a421edd428c29a3af5f0800e07eaf=). The Python implementation
uses Beautiful Soup to parse HTML into a passage model, then renders Org, Markdown, or
plain text directly. The original Ruby versions remain in Git history.

* Requirements
- Python *3.10 or newer*.
- Beautiful Soup 4 (=beautifulsoup4>=4.12,<5=). Its transitive dependencies are
  installed by pip or your distribution package manager.
- Internet access for live lookups. Offline tests use local synthetic HTML.
- Git for repository management.
- Optional: Emacs *27.1 or newer* with its bundled Org mode.
- Optional: =wl-clipboard= for clipboard copying on Niri/Wayland.

There is no compilation/build step when running from a checkout. Python's
standard library supplies networking, argument parsing, and the test runner.

* Install on Arch Linux
#+begin_src sh
sudo pacman -S --needed git python python-beautifulsoup4
#+end_src

If the repository already exists on your Forgejo instance:

#+begin_src sh
mkdir -p ~/devel
git clone forgejo:bwarkentin/biblegateway-export.git ~/devel/biblegateway-export
cd ~/devel/biblegateway-export
#+end_src

Alternatively, clone the downloadable repository bundle:

#+begin_src sh
mkdir -p ~/devel
git clone ~/Downloads/biblegateway-export-v2.2.0.bundle ~/devel/biblegateway-export
cd ~/devel/biblegateway-export
#+end_src

Run from the checkout:

#+begin_src sh
python ./bg-export --no-clipboard --format org "John 3:16"
#+end_src

Keep the complete checkout in =~/devel/biblegateway-export=. To run from anywhere,
link the executable into a directory already on your PATH:

#+begin_src sh
mkdir -p ~/scripts
ln -s ~/devel/biblegateway-export/bg-export ~/scripts/bg-export
#+end_src

=~/.local/bin= is another suitable location for the link. Existing links to
=bg-export= continue to work. Do not copy the launcher alone: it needs the
=biblegateway_export/= directory beside the real file.

** Other systems / virtual environment
Install Python, then create a virtual environment in the checkout:

#+begin_src sh
python3 -m venv .venv
.venv/bin/python -m pip install .
.venv/bin/bg-export --no-clipboard --format org "John 3:16"
#+end_src

For this setup, point the Emacs interpreter setting below to
=~/devel/biblegateway-export/.venv/bin/python=. Installing with pip also provides
the =bg-export= console command. Run =python -m biblegateway_export= as an
alternative entry point from a checkout or installed environment.

* Upgrade from v2.1.0
Download the new bundle and update a clean checkout:

#+begin_src sh
cd ~/devel/biblegateway-export
git fetch ~/Downloads/biblegateway-export-v2.2.0.bundle main --tags
git merge --ff-only FETCH_HEAD
#+end_src

This preserves your existing =origin=, including your Forgejo remote. No new
runtime dependency or required Emacs configuration change is needed. Restart
Emacs after upgrading, or reload =emacs/biblegateway-export.el= using
=M-x load-file= to activate the new prompts.
If you have local commits or edits that prevent a fast-forward, the provided
v2.2.0 patch is based on v2.1.0:

#+begin_src sh
git apply --check ~/Downloads/biblegateway-export-v2.2.0.patch
git apply ~/Downloads/biblegateway-export-v2.2.0.patch
git add .
git commit -m "Select passage, version, and format in Emacs"
#+end_src

When upgrading from the earlier Ruby v1.7.0 release, also install the Python
dependencies and replace =biblegateway-export-ruby-program= with
=biblegateway-export-python-program= in your Emacs configuration, then restart
Emacs. The insertion command and key binding keep their existing names.

* Usage
Save an Org passage for Emacs:

#+begin_src sh
mkdir -p ~/faith/biblestudy
python ./bg-export --no-clipboard --format org -v NET \
  --output ~/faith/biblestudy/john-3.org "John 3"
#+end_src

Save Markdown:

#+begin_src sh
python ./bg-export --no-clipboard --output john-3.md "John 3"
#+end_src

Save plain text:

#+begin_src sh
python ./bg-export --no-clipboard --format txt --output john-3.txt "John 3"
#+end_src

Plain text retains the passage title, editorial headings, verse numbers,
footnotes, cross-references, and copyright notice without generated formatting
markup. Bold and italics become ordinary text, line breaks become ordinary
newlines, and notes use simple =[a]= and =[A]= references and definitions.
=--boldwords= has no formatting effect in TXT. With =--newline=, chapters and
verses start on separate lines without heading markers. The existing exclusion
options work for TXT too. Literal characters in the passage itself are retained.

Markdown remains the default. Choose =--format org= or =--format txt= explicitly; the
filename extension does not select the output format. =--format md= is an alias
for =--format markdown=. Files use UTF-8; existing files are replaced, and parent
directories must already exist. Without =--output=, output goes to stdout.
Diagnostics go to stderr. Failures return a nonzero exit status.

References containing spaces can be quoted or supplied as multiple arguments.
Multiple noncontiguous passages or parallel translations are rejected: request
one at a time. Spacing and blank lines may differ from the Ruby output. Unicode
punctuation is preserved instead of replacing smart quotes and em dashes.

| Option                                    | Effect                                                               |
|-------------------------------------------+----------------------------------------------------------------------|
| =--format FORMAT=                         | markdown (alias md), org, or txt; default Markdown                   |
| =-o FILE=, =--output FILE=                | Write output to a file instead of stdout                             |
| =--no-clipboard=                          | Disable clipboard copying                                            |
| =--clipboard=                             | Attempt clipboard copying (default)                                  |
| =-v TRANSLATION=, =--version TRANSLATION= | Translation abbreviation; default NET                                |
| =-b=, =--boldwords=                       | Bold the words of Jesus in Org/Markdown                              |
| =-c=, =--copyright=                       | Exclude copyright notice                                             |
| =-e=, =--headers=                         | Exclude editorial headings                                           |
| =-f=, =--footnotes=                       | Exclude footnotes                                                    |
| =-r=, =--crossrefs=                       | Exclude cross-references                                             |
| =-n=, =--numbering=                       | Exclude chapter and verse numbers                                    |
| =-l=, =--newline=                         | Put chapters/verses on new lines; level 5/6 headings in Org/Markdown |
| =-i=, =--info=                            | Print lookup diagnostics to stderr                                   |
| =-t FILE=, =--test FILE=                  | Read local HTML; a reference argument is still required              |
| =--script-version=                        | Show program version                                                 |
| =-h=, =--help=                            | Show help                                                            |

Org uses star headings, =*bold*=, =/italics/=, =[fn:a]= footnotes, and native line
breaks. Cross-references use uppercase footnote labels. All three output formats are
rendered from the same parsed content; no Markdown-to-Org conversion is used.

* Emacs integration
The Emacs command prompts for a passage, Bible version, and format, then
inserts the result asynchronously into any writable buffer. It does not change
the destination buffer's major mode.

Add this to your init file or an Emacs Lisp source block in =bsw-emacs.org=:

#+begin_src emacs-lisp
(add-to-list 'load-path
             (expand-file-name "~/devel/biblegateway-export/emacs"))
(require 'biblegateway-export)

(setq biblegateway-export-script
      (expand-file-name "~/devel/biblegateway-export/bg-export")
      biblegateway-export-python-program "/usr/bin/python"
      biblegateway-export-translation "NET"
      biblegateway-export-default-format "auto")

;; Optional: choose another key if C-c b is already assigned.
(define-key org-mode-map (kbd "C-c b") #'biblegateway-export-insert)
#+end_src

This is also provided in =emacs/config-example.el=. After upgrading, restart
Emacs or reload =emacs/biblegateway-export.el= with =M-x load-file=.
Put point where the passage should go and run =M-x biblegateway-export-insert=
(or =C-c b= in Org buffers with the optional binding above). Answer:

1. =Bible passage:= for example, =John 3:16-18=.
2. =Bible version:= accept =NET=, select a suggested version using completion,
   or type any BibleGateway abbreviation. Suggestions are not an exhaustive list.
3. =Output format:= choose =org=, =md=, or =txt= using completion.

Press Enter to accept a displayed default. Minibuffer history is available for
all three prompts. The format defaults to =org= in Org buffers, =md= in Markdown
buffers, and =txt= elsewhere. To always offer a particular default:

#+begin_src emacs-lisp
(setq biblegateway-export-default-format "txt") ; or "org", "md", "auto"
#+end_src

The request runs in the background while you edit, and its insertion marker
follows edits. Insertion is a single undo group; selected text is not replaced.

For Org output, the passage becomes a child of the heading containing point when
you started the lookup. Before the first heading, or outside an Org buffer, it
starts at level one. Org footnote labels are made unique for each lookup. To
always insert top-level Org passages, set:

#+begin_src emacs-lisp
(setq biblegateway-export-heading-level 1)
#+end_src

Markdown and TXT are inserted as produced by the exporter, without Org heading
adjustment or footnote rewriting. If you insert multiple Markdown passages into
one document, their footnote labels are not automatically made unique.
Failures leave the destination unchanged and show an error buffer. If the note
closes or becomes read-only while fetching, the result is preserved in a separate
buffer with an appropriate mode. The command calls Python directly and disables
clipboard copying; it needs neither the =~/scripts= link nor a PATH change.

From Lisp, the optional third argument selects the format explicitly:

#+begin_src emacs-lisp
(biblegateway-export-insert "John 3:16" "NIV" "org")
(biblegateway-export-insert "John 3:16" "NET" "md")
(biblegateway-export-insert "John 3:16" "ESV" "txt")
#+end_src

The two-argument form remains supported and uses the configured buffer default.
Both =md= and =markdown= are accepted as the third argument.

* Clipboard
The Python implementation uses existing OS utilities instead of a clipboard
library: =wl-copy= on Wayland, =xclip=/=xsel= on X11, =pbcopy= on macOS, and
PowerShell on Windows. A missing or failing backend produces a warning; saving
or printing the passage still succeeds. Clipboard behavior has automated tests
for the Wayland command selection; other platforms are not verified here.

For your Niri setup:

#+begin_src sh
sudo pacman -S --needed wl-clipboard
bg-export --format org "John 3:16"
#+end_src

Alternatively, avoid automatic copying and use Emacs or a pipeline:

#+begin_src sh
bg-export --no-clipboard --format org "John 3:16" | wl-copy
#+end_src

* Tests
No test framework dependency is needed beyond the runtime dependencies:

#+begin_src sh
python -m unittest discover -s tests -v
emacs -Q --batch -L emacs -l tests/test_emacs.el -f ert-run-tests-batch-and-exit
#+end_src

If your test interpreter is not named =python3=, set =BG_TEST_PYTHON= to its
absolute filename when running the Emacs tests. The end-to-end Emacs test calls
the real Python exporter with synthetic HTML; no network request is required.

Tests cover formats, notes, headings, exclusions, Unicode, HTML variations,
file output, CLI errors, network failures, URL encoding, symlink execution,
clipboard fallback, and asynchronous Emacs insertion. Live NET, NIV, and LEB
samples were also checked during development. This does not guarantee every
translation or future BibleGateway markup will work.
